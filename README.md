# AI-агенты для Auto QA: шаблоны скиллов и материалы к докладу

Материалы к докладу Никиты Осипова на Heisenbug 2026 «AI-агенты для Auto QA: от хаотичных запросов к системной работе с навыками».

Что здесь лежит:

- три скилла: [`memory-init`](memory-init/SKILL.md), [`memory-update`](memory-update/SKILL.md), [`write-tests-by-task`](write-tests-by-task/SKILL.md);
- [`monday.md`](monday.md) — порядок действий на понедельник, семь шагов;
- [`research.md`](research.md) — ссылки на все исследования из доклада.

## Три скилла

Скилл — это инструкция в markdown, которую агент подключает под задачу. Шаблоны написаны под Java / Spring / JUnit 5, но специфика только в примерах: замените стек в тексте и они подойдут для любого языка.

| Скилл | Что делает | Когда запускать |
|---|---|---|
| [`memory-init`](memory-init/SKILL.md) | Аудит репозитория автотестов и создание памяти: `AGENTS.md` (≤150 строк) и `memory/` из восьми файлов | Один раз, до первой задачи |
| [`memory-update`](memory-update/SKILL.md) | Сверка памяти с кодом, вики и задачами, правки после подтверждения, история уточнений | После влитой фичи, смены библиотеки, по симптому |
| [`write-tests-by-task`](write-tests-by-task/SKILL.md) | Тесты по задаче из трекера: память → задача → план → одобрение → код → прогон → самопроверка → MR | На каждую задачу |

Скиллы написаны на английском: так их одинаково хорошо читает любая модель, включая развёрнутые внутри контура. README на русском, чтобы быстро сориентироваться.

Как подключить: положите папку скилла туда, откуда их читает ваш агент, и вызовите по имени.

| Агент | В репозитории | Глобально |
|---|---|---|
| OpenCode | `.opencode/skills/<name>/SKILL.md` (также читает `.claude/skills/` и `.agents/skills/`) | `~/.config/opencode/skills/<name>/SKILL.md` |
| Claude Code | `.claude/skills/<name>/SKILL.md` | `~/.claude/skills/<name>/SKILL.md` |

Адаптируйте под свой репозиторий: скилл, который знает ваши базовые классы и интеграции, работает лучше общего. В шаблонах упоминаются Jira, Confluence и GitLab через MCP: замените на свой трекер, вики и git-хостинг.

## Структура памяти

```
AGENTS.md              корневой файл, ≤150 строк: стек, карта памяти, жёсткие правила, стоп-сигналы
memory/
  project-overview.md  что тестируем, окружения, точки входа
  architecture.md      слои tests → steps → clients, базовые классы, контекст Spring
  conventions.md       именование, стиль, запреты
  test-patterns.md     шаблоны: REST, база, Kafka, WireMock, параметризованный
  frameworks-stack.md  библиотеки и версии
  workflow.md          семь шагов работы по задаче
  examples.md          3–5 эталонных тестов из репозитория как есть
  common-pitfalls.md   грабли именно этого проекта
```

Два правила: правда в коде, а не в памяти (разошлись — правьте память), и вся память должна помещаться примерно в четверть контекстного окна (иначе режьте примеры, а не правила).

## С чего начать в понедельник

То же самое отдельным файлом: [`monday.md`](monday.md).

1. Поставьте CLI-агента: OpenCode или разрешённый у вас аналог. Проверьте, какая модель под ним.
2. Создайте `AGENTS.md`: стек, версии, где лежат проверенные сценарии, что запрещено.
3. Запустите `memory-init` на репозитории автотестов.
4. Возьмите одну задачу на один контроллер. Сначала план, одобрили, потом код. Негативные кейсы просите на этапе плана. Зелёный прогон считается только против реального окружения, не стаба.
5. Чистите контекст между задачами (`/clear`). Половина окна — потолок, `/compact` только в сессии об одном.
6. Включите детерминированные проверки на CI: сборка, Maven Enforcer (версии), ArchUnit (слои и запрещённые импорты), Sonar, проверка, что у каждого теста есть ID кейса. Добавьте в скилл самопроверку теста.
7. Права по мере доверия: только чтение → подтверждение каждой команды → автономия. Автономия только в тестовом репозитории, с проверками на CI, откатом и стоп-сигналами в скилле.
