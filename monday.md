# С чего начать в понедельник

Семь шагов из доклада «AI-агенты для Auto QA» (Heisenbug 2026). Это не чек-лист на когда-нибудь, а порядок действий на первую неделю.

1. **Поставьте CLI-агента.** OpenCode или разрешённый у вас аналог (Claude Code, Codex CLI). Проверьте, какая модель под ним: качество «внезапно» падает, когда под обвязкой подхватывается модель поменьше.
2. **Создайте корневой файл `AGENTS.md`** (в Claude Code — `CLAUDE.md`): стек и версии, где лежат проверенные сценарии, что запрещено, стоп-сигналы, когда агент обязан остановиться и спросить. Не больше 150 строк.
3. **Запустите [`memory-init`](memory-init/SKILL.md)** на репозитории автотестов. Семь шагов, каждый с вашим подтверждением; в конце папка `memory/` из восьми файлов и самопроверка памяти по коду.
4. **Возьмите одну задачу на один контроллер.** Сначала план, одобрили, потом код ([`write-tests-by-task`](write-tests-by-task/SKILL.md)). Негативные кейсы просите на этапе плана. Зелёный прогон считается только на реальном окружении, не стаба.
5. **Чистите контекст между задачами** (`/clear`). Половина окна — потолок. `/compact` только в сессии об одном, иначе после сжатия получается каша.
6. **Включите детерминированные проверки на CI:** сборка, Maven Enforcer (версии Java и зависимостей), ArchUnit (слои и запрещённые импорты), Sonar, проверка, что у каждого теста есть ID кейса. Добавьте в скилл самопроверку теста: сломай логику, убедись, что тест упал, верни как было.
7. **Права по мере доверия:** только чтение → подтверждение каждой команды → автономия. Автономия только в тестовом репозитории, с проверками на CI, откатом одной командой и стоп-сигналами в скилле.

После первой влитой фичи запустите [`memory-update`](memory-update/SKILL.md): устаревшая память опаснее отсутствующей.
